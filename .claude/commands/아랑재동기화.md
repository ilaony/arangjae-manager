에어비앤비·부킹닷컴에서 **세 숙소**의 신규·변경·취소 예약을 찾고, 앱(Firestore)과 대조해 차이를 보고한다.

메일 조회 범위: 최근 **$1**일 (비어 있으면 7일). **단 캘린더 대조는 미래 전체**를 본다 — 메일이 안 온 예약이 실제로 있었다.

## 가장 중요한 규칙

**대조 결과를 먼저 보고하고, 사용자가 승인한 뒤에 쓴다.** 조회·대조는 승인 없이 진행하되, Firestore 쓰기는 절대 먼저 하지 않는다.

이유: 차이가 단순 반영이 아닌 경우가 많다. 실제로 나온 유형들 —

- 앱 이름이 `ㅇㅇ`·`dd`·`Dd` 같은 플레이스홀더여서 덮어쓸지 판단이 필요했다
- 변경 요청이 **이미 앱에 반영돼 있어** 또 쓰면 되돌릴 뻔했다
- 게스트 국적이 선택 목록에 없어서 **코드 수정이 필요**했다 (마카오, 뉴질랜드, 이탈리아·이스라엘·오스트리아)
- 거주지가 **동반자 것만** 표시돼서 일행 기준으로 추정해야 했다

기계적으로 쓰면 틀린 쪽으로 쓴다. 판단이 필요한 건은 반드시 사용자에게 올린다.

## 숙소와 식별자

| 앱 컬렉션 | 숙소 | 에어비앤비 리스팅 | 부킹닷컴 `hotel_id` |
|---|---|---|---|
| `arangjae-ara` | `[아라]광장시장/청계천…` | `1649288534400052206` | `16131113` |
| `arangjae-maru` | `[마루]명동/청계천…` | `1649530929908799202` | `16131113` |
| `daol` | `넓은 3룸 / 강남역…` | `979425845780379545` | `11003925` |

**다올은 별개 계정이지만 2026-10-28에 둘 다 연동됐다** — 에어비앤비는 공동 호스트, 부킹닷컴은 같은 익스트라넷 로그인의 두 번째 숙소다. 쓰기도 허용돼 있다.

**다올 알림 메일이 오는지는 아직 확인되지 않았다.** 그래서 다올은 메일에 의존하지 말고 아래 1·2번 경로로 본다. 다올 메일이 실제로 보이면 사용자에게 알린다 — 그러면 이 문서를 고칠 수 있다.

## 1. 에어비앤비 — 호스팅 목록 + iCal

**호스팅 `예정` 목록이 1차 소스다. 세 숙소가 한 화면에 섞여 나오고, 각 행에 이름과 인원이 함께 있다.**

```js
// mcp__aside__repl. 이미 열린 탭이 있으면 그것을 쓴다.
const t = await listBrowserTabs();
const p = await attachBrowserTab(t.find(x => /airbnb/.test(x.url)).targetId);
await p.goto("https://www.airbnb.co.kr/hosting?tab=upcoming");
// "더 보기"를 버튼이 사라질 때까지 누른다
```

행 형식: `11월 9일~10일 진우 님의 일행(4명) [아라]광장시장/…`. 숙소는 리스팅 이름으로 가린다(`[아라]` / `[마루]` / `넓은 3룸`). 이름 사이에 `⁠`(word joiner)가 섞여 있으니 **제거하고 비교한다.**

**이 목록은 다 렌더되지 않을 수 있다.** 헤딩이 "예약 29건"인데 28행만 그려진 적이 있다. 그래서 **iCal로 교차검증한다.**

```bash
# 토큰은 .claude/settings.local.json 의 permissions.allow 에 있다 (git 추적 안 됨)
curl -sL "https://www.airbnb.com/calendar/ical/<리스팅ID>.ics?t=<토큰>&locale=ko" -o x.ics
```

iCal 파싱 요령:

- **반드시 바이너리로 읽어 디코드한다** (`open(f,"rb").read().decode()`). 파이썬 텍스트 모드는 `\r\n`을 바꿔버려서 RFC 5545 줄펼침(`\r\n ` → ``)이 안 먹고 예약코드가 전부 빈다
- `DTSTART`=체크인, `DTEND`=체크아웃, `DESCRIPTION`의 상세 URL에 **예약코드**(`HM…`)가 있다
- **에어비앤비 iCal은 연박을 병합하지 않는다** — 날짜·전환일이 정확하다
- iCal에 이름·인원·국적은 **없다**

**취소 탐지는 iCal 비교가 가장 확실하다.** 지난 실행의 `.ics`가 스크래치패드에 남아 있으면 **지금 받은 것과 diff**해서 **사라진 건 = 취소**로 본다. 실제로 이 방법으로 마루 `ryono`(`HMHTEZCMSD`) 취소를 잡았다.

이름·인원 외에 **국적**이 필요하면 상세를 연다:

```
https://www.airbnb.co.kr/hosting/reservations/details/<예약코드>
```

상세에서 **`거주지: …`** 가 국적의 근거다. 주의할 점:

- **주 게스트의 거주지가 표시되지 않는 경우가 많다** — 동반자 것만 나온다. 그러면 일행 기준으로 추정하고 **"동반자 거주지 기반"이라고 밝힌다**
- 아예 아무도 거주지가 없는 건도 있다 → **기본값을 그대로 두고 "확인 못 함"으로 보고한다.** 이름으로 국적을 정하지 않는다
- 상세 페이지에서 `님의 일행(N명)` 을 정규식으로 잡으면 **사이드바 목록의 첫 행이 걸린다.** 본문만 보려면 마지막 `체크인` 이후 구간으로 잘라서 찾는다

## 2. 부킹닷컴 — 익스트라넷

**숙소별로 따로 조회한다.** 화면 좌측 상단 숙소 선택기로 전환할 수도 있지만(전환하면 새 탭이 열리고 그 탭은 REPL에서 닫히지 않는다), **URL에 `hotel_id`를 넣어 바로 가는 게 빠르다.** `ses` 값은 열려 있는 익스트라넷 탭 URL에서 가져온다.

```
목록: .../extranet_ng/manage/search_reservations.html
        ?ses=<세션>&hotel_id=<id>&lang=ko&date_type=arrival&date_from=&date_to=
상세: .../extranet_ng/manage/booking.html?ses=<세션>&hotel_id=<id>&lang=ko&res_id=<예약번호>
```

**`res_id`는 예약번호와 같다.** 목록 표의 `예약 번호` 열을 그대로 넣으면 된다.

표 읽기:

```js
const t = [...document.querySelectorAll('table')].find(x => /투숙객 이름/.test(x.innerText));
// 데이터 행: th,td 가 9칸이고 2번째 칸에 "YYYY년"이 있는 행
```

- **표는 비어 있는 채로 먼저 그려진다.** 행 수만 보고 판단하면 빈 행을 읽는다. **셀에 내용이 채워질 때까지** 기다린다
- 하단 `예약 로딩 중...` 은 사라지지 않는 고정 행이다. 그게 없어지길 기다리면 안 된다
- 한 번에 약 50건에서 잘린다. 넘으면 **날짜 구간을 쪼갠다.** 넓은 구간은 오류(`앗, 오류가 발생했습니다`)가 난다
- **열 구성**: 투숙객 이름 / 체크인 / 체크아웃 / 객실 / 예약 날짜 / **예약 상태** / 요금 / 수수료 / 예약 번호
- 상태가 `OK …`면 유효, `취소됨`이면 취소다. **취소도 같이 읽어야** 앱에 남은 취소분을 잡는다
- 인원은 이름 칸에 `성인 N명, 아동 M명 (나이)` 로 붙어 온다. 앱의 `guests`는 **아동 포함 총원**이다
- **현재 숙박 중인 건을 놓치지 않도록** 도착일 기준 조회를 오늘보다 앞에서 시작한다(예: 30일 전부터)

**국적은 상세에서만 나온다** — 투숙객 이름 바로 아래 **2자리 국가 코드**(`ca`, `tw`, `it`, `nz` …). 요청사항이 있으면 메모에 넣을 수 있다.

**REPL은 120초 제한이다.** 상세를 여러 건 돌 때는 **4건씩 나눈다.** 한 번에 10건 이상 돌리면 연결이 끊긴 것처럼 실패한다.

## 3. 메일 — 보조 수단

1·2번이 1차 소스다. 메일은 **변경 요청/수락**처럼 캘린더에 안 나타나는 사건과, 최근 움직임을 빠르게 훑는 데 쓴다.

```js
await googleAccounts.print();   // 아랑재 = ilaony@gmail.com, 보통 uid 0
await gmail.search(uid, 'from:airbnb.com after:YYYY/MM/DD');
await gmail.search(uid, 'from:booking.com after:YYYY/MM/DD');
```

**처리 대상:**

| 제목 패턴 | 뜻 |
|---|---|
| `예약 확정 - OOO 님이 …체크인할 예정` | 에어비앤비 신규 |
| `예약 변경 완료` / `OOO님이 예약 변경을 요청합니다` | 에어비앤비 변경 |
| `예약 취소` | 에어비앤비 취소 |
| `Booking.com - 신규 예약 안내! (번호, 날짜)` | 부킹닷컴 신규 |
| `Booking.com - 취소된 예약 안내! (번호, 날짜)` | 부킹닷컴 취소 |

**무시:** 후기 요청·후기 등록, `예약 알림: …곧 체크인`(기존 예약 리마인더), `예약 메시지가 전송되지 않았습니다`(메시지 템플릿 발송 안내), 광고(`discover@airbnb.com`), 게스트 메시지(`express@airbnb.com`, `*@guest.booking.com`), 숙박업 호스트 다이제스트, 익스트라넷 계정·비밀번호 관련 안내.

변경 메일은 **`예약 변경 완료`가 온 것만 확정**이다. `변경을 요청합니다`만 있고 완료 메일이 없으면 수락 여부를 알 수 없으니 "확인 필요"로 올린다. Gmail은 제목이 같은 변경 완료 메일을 한 스레드로 묶으므로 **스레드의 모든 메시지**를 봐야 한다 — 게스트가 다를 수 있다.

**메일에 없는 필드는 추측해서 채우지 않는다.** **부킹닷컴 신규 메일은 예약번호와 체크인 날짜만 준다** — 이름·인원·숙소·국적이 없으니 "그 번호가 앱에 있는가"까지만 검증하고, 상세가 필요하면 2번 경로로 간다. 빈 필드는 "값이 다름"이 아니라 **"출처에 없음"으로 따로 표시한다.**

## 4. 앱 데이터 조회

```bash
KEY=$(grep -o 'AIza[A-Za-z0-9_-]*' src/firebase.js)
B="https://firestore.googleapis.com/v1/projects/arangjae-manager/databases/(default)/documents"
for p in arangjae-ara arangjae-maru daol; do
  curl -s "$B/bookings-$p?key=$KEY&pageSize=500"
  curl -s "$B/cleaning-$p?key=$KEY&pageSize=500"
done
```

청소 컬렉션은 **문서 ID가 날짜 문자열**(`2026-11-10`)이다.

매칭은 **예약코드(`bookNumber`)가 있으면 그것으로** 한다. 세 숙소의 미래 예약에는 2026-10-28에 전부 채워뒀다. 없으면(대개 과거분) 숙소+체크인 날짜로 하고, **날짜 매칭은 추측이므로 결과에 그렇다고 표시한다.**

## 5. 대조 보고

표로 올린다 — 각 건마다 **출처 값 / 앱 값 / 제안 조치 / 근거(예약코드)**. 네 갈래로 분류한다:

1. **앱에 없음** → 추가 제안 (+ 퇴실일 청소 자동 등록)
2. **값이 다름** → 수정 제안, 어느 필드인지 명시
3. **취소됐는데 앱에 남아 있음** → 삭제 제안 (+ 그날 청소)
4. **이미 일치** → 한 줄로 "N건 일치"

숙소별로 나눠 쓴다. 판단이 필요한 건은 따로 떼어 **왜 애매한지** 쓴다. 그리고 멈춘다.

## 6. 승인 후 쓰기

승인받은 범위만 쓴다. **쓰기 전에 대상 문서를 스크래치패드에 백업한다** — 삭제·수정 모두.

예약과 청소는 **한 배치로 원자적으로** 커밋한다 (앱의 `saveBookingWithCleaning` / `deleteBookingWithCleaning`과 같은 동작):

```bash
curl -s -X POST \
  "https://firestore.googleapis.com/v1/projects/arangjae-manager/databases/(default)/documents:commit?key=$KEY" \
  -H 'Content-Type: application/json' -d @writes.json
```

> zsh에서 `"$B:commit"`은 `:c` 파라미터 수정자에 먹혀 URL이 깨진다. **위처럼 전체 URL을 그대로 쓴다.**

지킬 것:

- **쓰기 전에 날짜 겹침을 검사한다.** 추가분이 기존 예약이나 다른 추가분과 겹치면 올려서 묻는다 — 같은 방을 두 번 판 것일 수 있다
- **일부 필드만 고칠 때는 `updateMask.fieldPaths`를 쓴다.** 마스크 없는 `update`는 문서를 통째로 교체해서 나머지 필드가 날아간다
- **새 문서 ID**는 앱과 같은 방식으로 만든다 (`genId`, `src/App.jsx`):
  `Date.now().toString(36) + Math.random().toString(36).slice(2, 7)`
- 필드 타입: `stringValue`, `integerValue`(JSON 문자열로), `booleanValue`
- **신규 예약이면 퇴실일 청소를 같은 배치에 넣는다** — 문서 ID는 퇴실 날짜, `{status:"scheduled", auto:true, cleaner:"", memo:""}`. 그날 청소 문서가 이미 있으면 덮지 않고 그대로 둔다
- **삭제할 때 그날 청소도 지울지는 확인하고 지운다** — `auto:true`이고 `cleaner`가 비어 있고 **그날 퇴실하는 다른 예약이 없을 때만**. 담당자가 배정돼 있으면 남긴다
- **예약코드를 `bookNumber`에 넣는다.** 에어비앤비 `HM…` 코드도 넣는다 — 앱은 채널을 구분하지 않고 "예약번호"로 표시하므로(`booking.bookNumber &&`, `src/App.jsx`) 코드 수정 없이 동작한다
- **국적은 `NATIONALITIES`(`src/App.jsx`) 목록에 있는 값만 쓴다.** 51개가 들어 있다. 목록에 없는 국가가 나오면 임의로 넣지 말고 사용자에게 알린다 — 목록 밖 값은 나중에 편집 모달을 열 때 조용히 바뀐다. 목록에 추가하려면 코드 수정 + main 커밋(Vercel 배포)이 필요하고, **추가 전에 이미 저장된 국적 값 전체를 조사해 빠지는 게 없는지 확인한다**
- 흔한 코드 → 앱 값: `kr`→한국 `jp`→일본 `cn`→중국 `tw`→대만 `hk`→홍콩 `mo`→마카오 `us`→미국 `ca`→캐나다 `au`→호주(거주지 표기는 "오스트레일리아") `nz`→뉴질랜드 `it`→이탈리아 `de`→독일 `fr`→프랑스 `sg`→싱가포르 `il`→이스라엘 `at`→오스트리아
- 옵션 4개(`earlyCheckIn`, `lateCheckOut`, `luggageBefore`, `luggageAfter`)는 **확정된 요청일 때만** 켠다. 게스트의 희망 체크인 시간이나 방 선호(고층·조용한 방)는 해당하지 않는다

## 7. 검증과 보고

쓴 뒤 해당 문서를 다시 읽어 반영을 확인한다. 더해서:

- 숙소별 **예약 건수와 청소 건수**가 예상대로 늘었는지
- 미래 예약에 **퇴실일 청소 누락이 0건**인지
- 출처의 유효 예약 **전부가 앱에 있는지**(예약번호 집합 비교)
- 저장된 국적 중 **목록 밖 값이 없는지**

무엇을 왜 썼는지와 **백업 파일의 전체 절대 경로**를 보고한다. 조회 실패나 판단 보류로 **건너뛴 건이 있으면 명시**한다.

## 끝내기

**내가 연 탭은 닫는다.** 원래 열려 있던 탭은 건드리지 않는다. 익스트라넷 숙소 전환으로 열린 팝업 탭은 `page.close()`로도 닫히지 않으니, 남으면 사용자에게 직접 닫아달라고 알린다.

## 참고 — 채널별 함정

- **부킹닷컴 iCal은 쓰지 않는다.** 연박을 하나로 병합해서 중간 전환일(퇴실=입실인 날)이 사라지고, 그러면 그날 청소가 잡히지 않는다
- 부킹닷컴 취소 통보는 **예약번호만** 알려준다. 그래서 `bookNumber`가 유실되면 대조가 불가능하다
- 다올은 **체크인 17:00 / 체크아웃 12:00** 으로 아랑재(16:00 / 11:00)와 다르다. 앱은 날짜만 저장하므로 영향은 없다
- 청소 담당자는 다올이 주로 **김지영**, 아랑재 마루가 **이미영**이다. 자동 생성분은 `cleaner`가 빈 값이고, 배정은 사용자 몫이다
- Aside REPL은 **최상위 스코프가 계속 유지된다.** 호출마다 변수명을 새로 쓴다. 그리고 세션 폴더 밖의 파일은 읽지 못하니, 스크래치패드와 주고받을 때는 `pwd` 아래에 쓴 뒤 Bash로 복사한다
